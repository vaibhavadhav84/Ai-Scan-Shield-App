# Design Audit
Entry conditions: Existing UI or a requested redesign.
Inspection: Read screen code, requirements, API states and navigation; list implemented/blocked/deferred features.
Implementation: Record strengths, friction and three visual alternatives; choose an evidence-based direction.
Quality checks: Every implemented route and error/empty/loading state accounted for.
Failure handling: keep diagnostics free of private content; fix the concrete failure, rerun its relevant
check, and mark device/provider absence explicitly. Do not fabricate screenshots or test passes.
Completion: An actionable inventory and selected direction exist before visual edits.
